# 交付可靠性修复与验收

目标：修复首轮已复现问题，使用完整题集和真实工作流验证 100% 通过。原始失败永不覆盖；一次全通过只描述该轮观测，不保证随机模型永不失败。

## 实施前架构

- 领域与归属：沿用 Task、不可变 Submission、Review、Run、Session 和原任务线程。任务作者提交文件，指定审核者检查该版本，用户保留原有决策权。评测只操作自己的账号和资源。
- 生命周期：作者执行 → CLI 将实际文件序列化为证据 → 原提交 API 持久化 → 原审核队列派发 → 审核者从不可变提交导出文件并验证 → 原审核 API 记录结果 → 原线程反馈 → Run 正常结束。缺失证据和错误目标不能被算作成功。
- 已追踪调用链：前端 task-delivery-dialog/use-tasks → handler/task → service/task_delivery、task_review_dispatch、agent → durable Inbox/Run → daemon ProxyRequest/ExecutingCredential → 本地 provider Session → solo CLI → 原 API/PostgreSQL → WebSocket 与前端成果弹窗。
- 当前已证实缺口：审核派发缺少当前 target 头；复用 Session 中存在旧介绍线程。文件与 SHA 的手工复制会改变换行或产生错误哈希。现有验证器检查了引用和声明，不能代替审核者实际运行检查。介绍阶段超时原因仍需从真实 Runtime 轨迹定位。
- 数据流与 API：先补齐审核派发的明确回复目标；在 CLI 增加实际文件提交和精确版本证据导出，复用 get/submissions/submit，不增加服务器端文件读取接口。提交仍由服务器验证版本、权限、证据和幂等键。工具不求解、不访问隐藏测试。
- 文件边界：只读取调用者工作目录内的普通 UTF-8 文件，遵守服务端证据大小限制；导出仅写调用者显式指定的新文件，避免覆盖与符号链接。逐字保留换行，SHA 由程序计算或验证。URI-only 证据不能冒充已导出的内联文件。
- 持久化：继续使用现有 PostgreSQL 数据结构、不可变提交与证据，无新增数据库或持久化队列。派发消息头从当前 Task/线程生成，不从 Session 历史推测。
- 前端状态：沿用成果弹窗、任务状态和原线程，无新用户入口。真实 E2E 检查源文件、证据、版本、审核原因、可见结果和数据库状态。
- 审核：先读公开规格与不可变源码，程序校验哈希，逐项运行检查；拒绝必须有实际反例，修订不得凭审核者错误理解覆盖规格。通用审核指导在产品运行上下文内修复，不注入题目答案。
- 恢复：文件导出或校验失败时返回具体错误；不接受空材料。提交/审核沿用幂等规则，原任务中返工。Runtime 超时保留事件和实际用量，原因未证实前不提高分数或把缺失记零。
- 迁移与兼容：保留旧 CLI JSON 形式、human/agent/code Gate 权限、普通频道/DM/Thinking 路由、可授权的外部 URI 证据。新增文件快捷方式只用于文件型交付，不把 Git commit 版本错误替换为文件 SHA。无需迁移生产数据。
- 运行环境：在当前 3770 checkout 配置并通过仓库根 make rebuild 管理修复版栈；切换前通过原 a8d8 仓库 make stop 停止其服务。测试始终复用 make 管理栈，完成后恢复普通 Computer。
